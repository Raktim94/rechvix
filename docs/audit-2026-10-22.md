## Integration work

Zulivio's assignment service explicitly verifies an owner and related lead/opportunity belong to the actor's organisation. Rechvix had owner_user_id but no owner picker and relied on globally keyed foreign keys. Adapted that scoped-reference pattern into CRM Create/Update and a dedicated audited assignment action, with an active-user picker and cross-tenant database tests. No schema migration or dependency addition is required.

The CRM quotation button previously opened an ordinary empty tax invoice. It now passes the customer ID and quotation intent through typed route search. The composer fetches the permitted customer through its normal API, keeps resume-draft behavior and offers recovery if the customer cannot be loaded.

Mavri's DocumentEditor/PublicDocument/recurring workflows were compared with Rechvix's existing composer/share/recurring implementation. Rechvix already has those modules and integration tests; a second invoicing/payment database was not introduced. Remaining parity gaps are explicit: automatic assignment rules, management hierarchy, shifts/breaks, advanced manufacturing and offline synchronization. Current task does not claim these are implemented.

## Installer limitations

Shell regression tests use controlled command stand-ins in a temporary directory: they verify safety boundaries and failure handling, not actual Docker image builds. A full fresh Docker install and macOS/Windows host test remain unverified. Database migration and application workflow evidence is separate and must not be described as installer end-to-end proof. Do not claim external provider or jurisdiction certification from local tests.
